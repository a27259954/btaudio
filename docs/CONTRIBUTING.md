# Contributing

Thanks for your interest! BtAudio is meant to stay small: it keeps a phone connected as a Bluetooth audio source and fixes the connection with one click. Before you start a larger feature, please open an issue so we can agree on the scope.

## Setup

- Go 1.25+
- Node 20+
- Wails v3 CLI: `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.28`
- A paired phone, for manual testing

```bash
wails3 dev
```

```bash
wails3 task check
```

### Demo build (no phone needed)

This build is for UI work and screenshots:

```bash
wails3 task build EXTRA_TAGS=demo
```

The resulting exe shows two fake phones and a moving level meter, and keeps its settings in memory only. Set `BTAUDIO_LANG` (for example `zh-TW`) to pick the UI language. Close any running BtAudio first (`btaudio.exe --quit`), because only one instance runs at a time. The images in `docs/assets/` were made this way.

## Layout rules

- `internal/core` must stay free of Windows and Wails imports. Everything platform-specific goes through the `Backend` interface, and behaviour changes come with a test against the fake backend in `manager_test.go`.
- `internal/audio` is the only package that makes WinRT/COM calls. Write each vtable index with a comment that names the method.
- Frontend bindings in `frontend/bindings` are generated by `wails3 build`. Never edit them by hand.
- UI strings live in `frontend/src/i18n.js`, and `en` is the source. `npm run check` fails if a language is missing a key. To add a language, add its dictionary and its `LANGUAGES` entry, then add it to `Supported`, `Resolve` and the tray labels in `internal/lang/lang.go`.
- UI: keep it compact. Use the CSS tokens in `frontend/src/style.css`. No UI kits and no explanatory copy in the window.

## Commits and PRs

- Keep PRs focused. Describe the user-visible change and how you tested it, including the phone and Windows version if it touches Bluetooth.
- `go vet ./...`, `go test ./internal/...` and `npm run check` must pass. CI runs all three.

## Releases

Releases are automatic. Every push to `main` that touches code runs `.github/workflows/release.yml`, which tests the commit, builds `btaudio-v<version>.exe` (the version is in the file name and in its Properties → Details) and publishes a GitHub release with a SHA-256 checksum.

- **Version:** `v<VERSION>.<n>`. `VERSION` holds the minor line (for example `0.1`), and `n` counts up from the existing tags (`v0.1.0`, `v0.1.1`, …). Edit `VERSION` to start a new line.
- **Skipped automatically:** pushes that only change Markdown, `docs/`, `LICENSE` or issue templates.
- **Skip by hand:** put `[skip release]` in the commit message.
- **Release notes** are generated from the commits since the previous tag.
